## 1. 정체성 한 장

- **무엇**: 〈운영자 실명〉의 SCM 작업실. 수도권 공급망이 인천을 어떻게 지나가는지 실제 데이터를 움직여 보여 준다.
  - **[2026-10-22 선장님 최종 결정 · 대체]** 홈(첫 화면과 홈 전체)은 사이트 「측심」으로 보인다 — 실명·학교·자격·채용 줄은 **소개 지면에만** 둔다(소개로 가는 링크로 충분). 홈 첫 화면 대상 = 물류·무역·유통 실무자. 기준 = `docs/품질기준.md` Q9~Q11.
- **주장**: 수도권 공급망의 관문은 인천이고, 앞으로 더 그렇게 된다.
- **정직 장치**: 주장에 불리한 지표도 숨기지 않는다. 지도와 노트는 편마다 **인천이 약한 반대 지표를 하나 이상** 같은 화면에 둔다. 아직 못 찾았으면 「반대 지표 — 아직 못 찾음」이라고 적는다. 반대 지표 칸이 빠진 편은 공개하지 않는다.
- **대상과 각자 얻어 가는 것**
  - 물류·SCM 실무자: 자기 일이 수도권 지도 위 어디에 있는지 보고, 틀린 곳은 교정해 준다.
  - 채용 담당자: 이 사람이 데이터를 어떻게 다루고 판단하는지 결과물로 본다.
  - 기자: 인천·수도권 물류 숫자를 출처와 함께 가져간다.
- **표기 메모**: 이 문서의 〈운영자 실명〉 자리는 공개 전환 PR에서 실명으로 바뀐다(§5-4). 그 전에는 저장소에 실명을 적지 않는다.
- **소개 페이지(공개 전환 때 반영)**: 실명, 인하대 아태물류학부, 자격 5종, 커넥터스 기고, 연락처. 연락처는 선장님이 공개용으로 고른 것 하나만 쓰고 그 값은 선장님이 준다. 이 문서에는 적지 않는다.
- **이름**: 사이트 이름 「측심」을 유지할지, 「SCM 작업실」을 앞에 세울지는 [미정]이다. 정해질 때까지 기본값은 「측심」 유지이고, 정체성 문장은 부제로 둔다. 선장님 한마디로 정한다.

## 2. 구조 넷과 공통 규칙

**구조**: ① 지도(본체 — 수도권·인천 공급망 네트워크) ② 시뮬레이션 ③ 노트 ④ 소개.

1. **숫자는 데이터 파일에서만**: 화면에 뜨는 수치는 전부 `data/`·`analysis/`의 파일에서 빌드 때 읽는다. 페이지·컴포넌트 본문에 직접 적은 수치는 0이어야 한다. 콘텐츠마다 PR에 검사 스크립트를 함께 넣는다. 연도·날짜·단위, 시뮬레이션 규칙 상수(규칙 문서에 출처가 있는 것)는 예외로 둔다.
2. **노트는 짧게, 날짜를 박아서**: 제목이나 머리에 `YYYY-MM-DD`가 들어가고, 본문은 1,500자 이하. 긴 보고서 형식은 새로 만들지 않는다. 이미 발행된 편은 본문을 한 글자도 바꾸지 않는다(기준 18의 원칙).
3. **만든 사람 노트 3줄**: 지도·시뮬레이션·노트 모든 콘텐츠에 「왜(왜 만들었나) · 어떻게(데이터와 방법) · 한계(이걸로 말할 수 없는 것)」 세 줄을 붙인다. 하나라도 빠지면 검사가 실패한다.
4. **AI 표기**: AI가 만든 글·요약·코드 산출물에는 「AI 정리 · 〈운영자 실명〉 검수」를 단다. 검수(통독과 수치 대조)를 실제로 한 것에만 단다. 검수 전인 것은 공개하지 않는다. 사람이 쓰지 않은 것을 사람이 썼다고 적지 않는 규칙(§2.2-4)은 그대로다. AI 영상·이미지의 「AI 생성 장면」 표기(기준 19)도 그대로 둔다.
5. **갱신일과 출처**: 위젯마다 「마지막 갱신일」과 원천 링크를 단다(기준 14·16).

## 3. 1차 공개 넷 + AI 운영실 사례 — 콘텐츠별 기준

판정일은 **그 콘텐츠의 공개일 + 28일**이다. 공개일은 Pages에 실제로 뜬 날이다. 「대화·연락」과 「피드백」은 jota `metrics/`에 채팅이 남긴 값만 센다(LinkedIn 댓글·메시지, 메일, 실무자 대화). 방문 수는 Cloudflare Web Analytics 경로 집계로 참고만 하고 성공·폐기 판정에는 쓰지 않는다(이벤트를 잴 수 없다 — 기준 29).

### 3-1. 맥주 게임 (채찍효과 체험) — 데이터 대기 없음, 첫 번째로 만든다
- 공개 전 완성 기준(하나라도 못 넘으면 공개 안 함)
  - G1 규칙: 4단계(소매 · 도매 · 유통 · 공장), 주문·배송 지연, 재고·백오더 비용. 원 규칙의 출처를 화면 「어떻게」 줄에 적는다(Sterman 1989, *Management Science* 35(3)). 규칙 상수는 출처와 함께 `data/`의 설정 파일 하나에 둔다.
  - G2 재현: 같은 시드와 같은 주문이면 같은 결과가 나온다. 로직 단위 테스트가 이 고정 결과를 잰다.
  - G3 채찍효과 숫자: 끝나면 단계별 주문 변동 증폭비(그 단계 주문의 분산 ÷ 소비자 수요의 분산)와 총비용을 보여 준다. 계산은 테스트로 고정한다.
  - G4 서버 0: 서버 저장·전송 0, 외부 요청 0(기준 17 예외만), 쿠키 0. 결과 공유는 주소 안의 값으로만 한다(기준 8 방식).
  - G5 휴대폰: 360px에서 가로 넘침 0, 한 판을 끝까지 둘 수 있다.
  - G6 만든 사람 노트 3줄, AI 표기(§2).
- 성공(판정일까지 하나 이상): 이 게임을 두고 온 실무자·채용 측 대화나 연락 1건, 또는 수업·교육·사내 교육에 쓰고 싶다는 요청 1건, 또는 규칙·계산 교정 피드백 2건. 그리고 LinkedIn 1편.
- 폐기: 셋 다 0이면 게임은 두고(유지비 0) **시뮬레이션 갈래에 새 게임을 더 열지 않는다.**

### 3-2. 공급망 따라가기 (상품 하나가 해외에서 수도권 소비자까지)
- 완성 기준
  - S1 상품 고르기 규칙: 구간마다(해외 출발 → 해상·항공 → 인천 입항·통관·보세 → 물류센터 → 수도권 배송) 공개 원천 데이터가 하나 이상 있는 상품으로 고른다. 원천이 없는 구간은 화면에 「이 구간 데이터 없음」이라고 적는다. 지어낸 값은 0이다.
  - S2 지도: 네트워크 지도 위를 스크롤하며 5단계 이상 따라간다. 타일은 내장 PMTiles이고 실행 중 키는 0. 첫 화면은 정지 이미지다(기준 20).
  - S3 반대 지표 1개 이상(§1). 예를 들면 그 상품이 인천이 아닌 다른 항만으로 들어오는 비중.
  - S4 화면 수치 = 데이터 파일. 스크립트 대조 불일치 0.
  - S5 360px 가로 넘침 0. 만든 사람 노트 3줄과 AI 표기.
- 성공: 판정일까지 실무자·채용 측·기자 대화나 연락 1건, 또는 구간 교정 피드백 1건. 그리고 LinkedIn 1편.
- 폐기: 0이면 지도 본체는 두고 **두 번째 상품 서사를 만들지 않는다.**

### 3-3. 인천항 선박 리플레이 (입출항 기록)
- 착수 조건: 선박 단위 입출항 원천(기관·이용허락·갱신 주기)을 출처 대장에 먼저 올리고 공공누리 유형을 확인한다. 지금 저장소에 있는 것은 월 집계(`data/collected/vessel-harbor.csv` — 월별 입항·출항 척수와 톤수)뿐이다. 선박 단위 원천이 확인되지 않으면 **월 집계 리플레이로 축소**하고, 화면에 「월 집계 — 개별 선박 아님」이라고 적는다.
- 완성 기준
  - V1 원천 행 수와 기간이 화면 집계와 같다(스크립트 대조).
  - V2 갱신은 Actions 예약 실행으로 한다(Claude 토큰 0). 키는 저장소 시크릿으로만 넘기고, 실행 중 키는 0.
  - V3 반대 지표 1개 이상, 갱신일, 만든 사람 노트 3줄과 AI 표기, 360px.
- 성공·폐기: 3-2와 같은 문턱(대화·연락 1건 또는 교정 1건 + LinkedIn 1편 / 0이면 확장 중단, 화면은 둔다). 변경 금지(3·4유형) 원천이면 가공하지 않거나 그 원천을 쓰지 않는다(기준 16).

### 3-4. 인천항 수요예측 실험실 (3개월 예측 + 매달 적중률 공개)
- 선커밋 — 첫 예측 전에 따로 문서(`docs/수요예측_방법론_선커밋_YYYYMMDD.md`)로 커밋한다. 대상 계열(기본값 인천항 컨테이너 월간 처리량 천TEU, `analysis/terminal_monthly*.csv`), 모델, 기준선(계절 나이브 = 작년 같은 달), 오차 지표(MAPE와 증감 방향 적중), 발표일을 적는다.
- 완성 기준
  - F1 예측 원장은 덧붙이기만 한다: `data/`의 원장 파일은 행을 덧붙이기만 하고 지우거나 고치지 않는다. 틀린 예측도 남긴다. 기존 행이 바뀌면 CI가 실패한다.
  - F2 예측이 먼저 커밋된다: 각 예측 행은 해당 월 실제값이 발표되기 전에 main에 들어간 커밋으로 증명한다.
  - F3 매달 실제값이 나오면 적중률(모델 대 기준선)을 같은 화면에 갱신한다. 기준선에 졌으면 졌다고 적는다.
  - F4 만든 사람 노트 3줄(한계에 「3개월 예측은 정책·운임 충격을 못 본다」 같은 내용), AI 표기, 갱신일.
- 성공: 3개월 연속으로 예측 → 실제값 대조가 끊기지 않고 원장 무결(F1·F2). 그리고 LinkedIn 1편. 그리고 판정일까지 실무자·채용 측·기자 대화나 연락 1건.
- 폐기: 원천 월간 발표가 2개월 연속 끊기면 실험실을 멈추고 「중단 — 원천 끊김」으로 남긴다(원장은 지우지 않는다). 모델이 3개월 연속 기준선보다 나쁘면 모델을 내리고 기준선만 공개한다. 실험실은 둔다.

### 3-5. AI 운영실 공개 사례 1쪽
- 완성 기준
  - O1 내부 노출 0: jota 경로·과제 번호·결재함 내용·회의 원문·사람 이름(선장님 제외)·키·계정 정보가 하나도 없다. 수치 요약만 담는다.
  - O2 수치는 데이터 파일에서: 집계 명령과 기준일을 같이 적는다(예: 기간 안 루틴 회차 수, 머지된 PR 수, 사람이 고친 비율). 집계 명령이 없는 수치는 쓰지 않는다.
  - O3 만든 사람 노트 3줄, AI 표기.

### 3-6. 3PL 계산기 흡수 검토 (판정만 — 이 라운드에서 만들지 않는다)
