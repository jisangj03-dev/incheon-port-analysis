# 측심 갱신 무인화 — 판정 기준 선커밋(2026-10-22)

> 지시: 채팅 · 10/22 선장님 승인 「과제 3: 갱신 무인화 완성」. 이 문서는 **구현보다 먼저** 커밋한다(헌법 3 · 선커밋).
> 목표: 공개·홍보 뒤 선장님이 따로 신경 쓰지 않아도 측심이 스스로 최신·정확하게 돈다. 선장님 몫은 **문장 확인 PR 결재**와 **사람 손이 필요한 경보**(키 재발급 등) 둘뿐.
> 첫 사례: 홈 띠 그림 「서울시청 52분」(화물차·낮) ↔ 지면·초안 「51분」(승용차·낮). 실측 결과 띠 그림은 배포 때마다 다시 찍혀 **낡지 않았다** — 기준(차종)이 달랐다. 그래서 막을 것은 「낡음」이 아니라 **「같은 숫자가 다른 기준으로 두 곳에 나가는 것」**이다.

## 경계(바꾸지 않는다)
반복 작업은 GitHub Actions(공개 저장소 · Claude 토큰 0 · 무료 분량) · 공개 화면 외부 요청 0(Cloudflare 분석 1개 예외) · Max 밖 지출 0 · 키는 저장소 시크릿으로만 · 세션이 키로 원천을 직접 부르지 않는다(사고 132) · 모의 시험은 main·공개판에 쓰지 않는다.

## 성공 기준 — 다섯 갈래(각각 확인 명령이 있다)

| # | 끝난 상태 | 통과 기준 | 확인 |

| ③ 해석 | 해석 문장(반대 지표·순위·「대부분」·「절반」)에 조건이 걸려 있어, 숫자가 바뀌어 뜻이 뒤집히면 자동 배포 대신 **문장 확인 PR** 이 올라온다 | (a) 해석 문장은 `data/claims.json` 대장에 조건·두 갈래 문장·승인 갈래로 등록 · (b) 지금 갈래 ≠ 승인 갈래면 시험이 빨강 · (c) refresh 는 그때 main 에 쓰지 않고 배포하지 않고, 승인 갈래만 바꾼 PR(라벨 `문장확인`)을 연다 — 머지 = 선장님 결재 | `python tools-build/claims.py --check` · 시험 `claims.spec` |
| ④ 실패 | 원천 형식 변경·키 만료·실패 시 해당 지면에 「갱신 지연」이 자동 표시되고, 사람 손이 필요한 실패만 jota 비서실 07:30 브리핑에 올라온다 | (a) 받기 단계는 일시 오류(시간 초과·5xx·연결)를 같은 회차에 다시 시도한다 · (b) 지연 판정: 키·인증 오류 / 형식 오류 / 이틀 연속 실패 / 마지막 확인이 주기 한도를 넘음 / 원천이 냈는데 지면이 뒤처짐 → 그 원천을 쓰는 지면 출처 줄에 「갱신 지연」 · 배포는 막지 않는다(다른 원천 갱신은 나간다) · (c) 사람 손 = 키·인증 · 형식 · 사흘 연속 실패 · 뒤처짐 → 이슈(라벨 `자동경보`) · 다시 성공하면 이슈를 스스로 닫는다 · (d) jota Action(07:05 KST)이 공개 API 로 그 이슈·문장확인 PR·마지막 refresh 실행을 읽어 jota 이슈 「측심 자동 경보」(라벨 `측심`)를 열고 닫는다 → 비서실 브리핑 `## 이상 신호` 가 그 이슈를 옮긴다 · (e) 일시 오류가 재시도로 풀리면 아무에게도 올리지 않는다 | `data/derived/health.json` · 시험 `freshness.spec` |

## 모의 시험 3종 — Actions 에서 실행 증명(선커밋 기대값)
모의는 `claude/` 브랜치에서 `refresh` 를 `mock` 입력으로 돌린다. **main·공개판·배포 0**, 모의가 연 이슈·PR 은 제목에 `[모의]`, 증명 뒤 닫는다.

| 모의 | 하는 일 | 기대(이대로 안 되면 실패) |
|---|---|---|
| M1 원천 변경 | 받은 원천 파일 하나를 새 공표처럼 바꾼다(외항선 최신 달 척수) | 파생 → 핵심 숫자·지면·도구 초안·홍보 초안·띠 그림 guard 가 **같은 새 값**으로 다시 만들어지고 시험 초록 → 「자동 반영(커밋·배포 대상)」 판정 · 사람에게 올림 0 |
| M2 원천 끊김 | 한 원천 받기를 ⓐ 일시 오류 1회(재시도로 풀림) ⓑ 인증 오류로 끊는다 | ⓐ 재시도 성공 · 지연 표시 0 · 경보 0 · ⓑ 그 원천 지면에 「갱신 지연」 · 시험 초록(배포는 막지 않음) · `자동경보` 이슈 열림 → jota Action 이 jota 이슈로 옮김(비서실 브리핑 입력) |
| M3 해석 뒤집기 | 반대 지표의 두 몫이 뒤집히게 원천 값을 바꾼다 | 시험·대장이 뒤집힘을 잡고 main 커밋·배포 0 · 승인 갈래만 바꾼 `[모의]` 문장 확인 PR 이 열린다 |

## 폐기·축소 기준(선커밋)
- 문장 확인 PR 이 한 달에 4건을 넘으면(같은 문장이 오가며 결재가 일이 된다) 그 문장은 조건을 넓히거나 해석을 걷는다 — 결재 부담이 목표(신경 안 씀)를 넘으면 실패다.
- 경보 이슈 가운데 사람이 손댈 것이 없던 것(스스로 풀린 것)이 4주에 2건을 넘으면 분류 규칙을 고친다(사람에게 소음을 올린 것).
- 정기 점검이 바깥 사이트 차단만으로 4주 연속 경보를 내면 그 링크 검사는 「확인 불가」 목록으로만 둔다.
- 11/19(4주)에 이 표로 다시 잰다 — 기록은 `docs/작업기록.md`.

## 하지 않는 것
- 해석 문장을 자동으로 고쳐 쓰지 않는다(두 갈래 문장은 사람이 미리 쓴 것만 · 갈래 전환도 PR 결재).
- 일시 오류를 사람에게 올리지 않는다. 경보는 사람이 할 일이 있을 때만.
- 모의 결과를 main 에 쓰지 않는다.
