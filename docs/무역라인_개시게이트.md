# 무역 라인 개시 게이트

> **게이트 ① 통과 (2026-08-26).** 관세청 2종 모두 실호출 성공.
> 게이트 ②는 **값을 보기 전에** 이 문서에 썼다. 근거: 지침 §5.0 · 설계 v2 §5.3.

## 왜 무역이 다음인가 [확정 · 설계 v2 §4]

산업 확장 순서는 **물류 → 무역 → 유통**이다. 무역이 먼저인 이유는 하나다.

**관세청 「항구·공항별 수출입실적」이 기존 인천항 시리즈와 같은 대상을 다른 소스로 본다.**
첫 무역 편이 곧 기존 7편의 최대 한계를 푸는 편이 된다 —
`report_07` §4.1 한계 ③ *「단일 소스다. 공컨테이너 물동량 API 하나에서만 가져왔다.
다른 기관 통계와의 교차 확인은 하지 않았다.」*

즉 무역 라인의 첫 편은 새 축을 여는 것이 아니라 **이미 발행한 결론을 다른 신고 체계로 대조**하는 것이다.

## 게이트 ① 소스 실재 확인 — **통과 (2026-08-26)**

```
python analysis/probe_customs.py          # 종료코드 0
```

**실측 이력**

| 일시 | 항구·공항별 수출입실적 | 세관장확인대상물품 | 대조군(공컨) |
|---|---|---|---|
| 2026-08-25 | 막힘 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(30) | 막힘 (동일) | — |
| 2026-08-26 (활용신청 전) | 막힘 **HTTP 403** | 막힘 **HTTP 403** | 정상 `200 / code=00` |
| **2026-08-26 (활용신청 후)** | **개통 `200 / code=00` · 511행** | **개통 `200 / code=00` · 6행** | 정상 `200 / code=00` |

**활용신청은 자동승인·개발계정이었고, 별도 키 발급이 없었다.**
data.go.kr 인증키는 계정 단위라 **`config.py`의 기존 키가 그대로 통했다** — 실측으로 확인했다.

> **[해소] 403의 원인.** 미승인이었다. 경로는 처음부터 맞았다.
> 승인 후 두 엔드포인트 모두 같은 URL로 200을 냈다.
>
> **[신규 사고 36] 승인이 풀리자 프로브 자신의 결함이 드러났다.**
> 세관장확인대상물품은 승인 후에도 `code=99`였고, 사유는 「필수 요청변수가 누락되었습니다」였다 —
> **필수 파라미터 `imexTpcd`(수출입구분)를 우리가 안 보내고 있었다.** 403에 가려 안 보였을 뿐,
> 이 프로브는 **승인이 나도 영원히 「막힘」이라고 보고할 상태**였다.
> **처분:** 판정을 셋으로 갈랐다 — `개통` / `요청이상`(HTTP 200인데 실패 = 우리 잘못) / `막힘`(도달 실패).
> 그리고 0행 응답을 개통 증거로 치지 않는다(사고 5) — 행이 실제로 오는 조합으로 고정했다.

## 소스 스키마 — 실측. **값은 보지 않았다**

```
python analysis/probe_porttrade_schema.py [--dims] [--structure]
```

이 프로브는 **축은 그대로, 값은 마스킹**한다. 값을 본 뒤에 쓰는 질문은 선커밋이 아니기 때문이다(사고 8·21).
**마스킹은 스크립트가 한다** — 사람이 「안 보겠다」고 다짐하는 방식은 방어가 아니다(사고 30).

| 태그 | 지위 | 내용 |
|---|---|---|
| `year` | 축 | **YYYYMM 6자리 — 월 단위다** |
| `cstmSgn` | 축 | 신고 세관 부호 (3자리) |
| `portCd` | 축 | 항구·공항 코드. **`KRINC` = 인천항** |
| `statKor` | 축 | `portCd`의 한글 라벨 |
| `expCnt` `impCnt` | **값** | 수출·수입 **건수** |
| `expDlr` `impDlr` | **값** | 수출·수입 **달러** |
| `balPayments` | **값** | 수지 |

**응답 골격 — 합산 전에 알아야 할 것 넷.**

1. **`numOfRows`가 안 먹는다.** 1을 보내든 99999를 보내든 **월 전량이 온다**(2026-01: 511행).
   페이징이 없다. `numOfRows=1`로 「1행만 받았다」고 가정하면 사고 4 계열의 오독이 된다.
2. **`totalCount` 태그가 없다.** 완결성 확인(사고 3)을 응답 메타로 못 한다 — **행 수를 직접 센다.**
3. **집계행이 명세행과 같은 응답에 섞여 온다.** `portCd`·`statKor`이 `-`인 행 1건이 총계다.
   그 행에는 `cstmSgn` 태그 자체가 없다 — **행마다 태그 구성이 다르다.** 위치 인덱스 금지(사고 1)가
   여기서 선택이 아니라 필수다. 합산 시 이 행을 빼지 않으면 **정확히 2배가 된다.**
   동시에 이 행은 **검산 대조군**이다 — 명세 합 = 총계.
4. **잔여 범주가 있다** — `기타항` · `기타불개항`. 인천항에 섞여 있지 않지만 전체 합에는 들어간다.

**인천항의 분해.** `KRINC` 행이 **월 40~42건**이다 — 인천항 실적이 **신고 세관별로 쪼개져** 온다.
인천항 값을 쓰려면 그 달의 `KRINC` 행 전부를 합해야 한다.
**`ICN`(인천국제공항)·`KRGIN`(경인항)은 별개 코드다.** 인천항은 `KRINC` 하나다.

**월 도달 실측** — 2024-12 · 2025-12 · 2026-01 · 2026-03 · 2026-06 · **2026-07** 전부 응답 있음.
**공컨 API(2026-06까지)보다 한 달 더 나간다.**

> **본 것의 한계를 적는다.** 마스킹 형식이 값의 **자릿수**를 노출한다(「숫자 4자」).
> 값 자체는 한 번도 안 봤지만, 자릿수를 봤다는 사실은 남긴다. 게이트 ②는 자릿수로 쓸 수 있는 질문이 아니다.

## 게이트 ② 개시 선커밋 — **통과 (2026-08-26)**

### 대상을 공컨에서 적컨으로 바꾼다 — 설계 근거

원안은 「인천항 **공컨테이너** 물동량을 관세청 신고로 교차 확인」이었다. **성립하지 않는다.**

관세청 실적의 값은 **수출입 신고의 건수·금액**이다. 빈 컨테이너는 화물이 아니라 운송 용기이므로
**신고 금액이 붙지 않는다** — 즉 공컨은 이 데이터에 잡히지 않는다. **[미확인]** 이 전제는
정의문이 아니라 도메인 판단이고, 확인 수단은 첫 수집 후의 검산이다.

그래서 교차 확인 대상을 **적컨(화물) 방향**으로 옮긴다. 마침 그쪽에 이미 발행한 결론이 있다 —
`report_05`: **「적컨은 수입, 공컨은 수출」**. 그 절반(적컨 = 수입 우위)이 다른 신고 체계에서도
관측되는지가 이 라인의 첫 질문이다. **전제가 틀렸어도 질문은 선다** — 공컨이 잡힌다면 그것 자체가 발견이다.

### 질문 3개

| | 질문 | 답하는 축 |
|---|---|---|
| **Q1** | 관세청 신고 기준으로 **인천항은 수입 우위인가 수출 우위인가.** 금액(`Dlr`)과 건수(`Cnt`)를 각각 본다 | `KRINC` × `year` × 값 4종 |
| **Q2** | 그 방향이 **확인된 창(2024-12 ~ 2026-07)에서 몇 개월 연속 성립하는가** | 월별 부호 연속성. `report_04`·`06`의 방법을 그대로 이식한다 |
| **Q3** | **건수 기준 방향과 금액 기준 방향이 어긋나는 달이 있는가** | 어긋나면 그 달이 곧 산출물이다. 한 소스 안의 내적 비대칭이라 결합 게이트를 안 탄다 |

**Q3을 넣은 이유.** Q1·Q2는 다른 소스와의 결합이 필요하지만 **Q3은 관세청 데이터 안에서 닫힌다.**
결합 게이트가 어디서 깨지든 Q3은 답이 나온다 — **라인이 한 번에 무너지지 않게 하는 질문**이다.

### 데이터 축

- **기간** 2024-12 ~ 2026-07 (실측으로 응답 확인된 구간. 그 밖은 확인하고 넓힌다)
- **모집단** `portCd = KRINC` 인 행 전부. 월별로 `cstmSgn`을 가로질러 합산한다
- **단위** 건수 · USD. **TEU·박스 수가 아니다**
- **제외** `portCd = '-'` 총계행. 단 **명세 합 = 총계** 검산에는 쓴다

|---|---|

| 인천항만공사 공컨테이너 화물 통계 | 기존 시리즈 소스. **맞대는 쪽** |
| `report_05` | 적컨 수입 우위 결론의 출처. 대조 대상 |

### 결합 게이트 — 먼저 판정한다 [지침 §3-9]

**두 소스는 값을 직접 맞댈 수 없다.** 셋이 전부 다르다.

| | 공컨 API | 관세청 |
|---|---|---|
| 단위 | TEU · 박스 수 | 신고 건수 · USD |
| 모집단 | 항만공사가 집계한 컨테이너 취급 | 세관에 신고된 화물 |
| 집계 주체 | 인천항만공사 | 관세청 |

**그래서 첫 편은 값을 맞대지 않고 방향(부호)만 맞댄다.**
배율을 내지 않는다 — §3-9가 「비정수 배율은 축 불일치 신호」라고 적은 상황이 **처음부터 성립**해 있다.
**이 축소는 은폐가 아니라 선언이다.** 첫 편 본문에 이 표를 그대로 싣는다.

## 게이트 ③ 성공 조건 — **확정 (2026-08-26)**

**데이터를 받기 전에 못 박는다.**

| | 기준 | 판정 |
|---|---|---|
| **A** | Q1·Q2·Q3에 **전부 답이 나온다** | 답이 「판정 불가」여도 사유가 적히면 통과 |
| **B** | **명세 합 = 총계 검산이 성립한다** (`KRINC` 포함 전 항구 합 vs `portCd='-'` 행) | 안 맞으면 그 자체를 먼저 규명한다. 발행 보류 |
| **C** | 결론 자리 수치가 **전부 `FACTS.md` 등재 + 창·지위 부착** | 린터 FAIL 0 |

**어긋나도 성공이다.** 두 소스의 방향이 반대로 나오면 그것이 발행 가치다 —
그 경우 **어느 쪽이 옳은지 단정하지 않고** 차이의 방향과 그 구조적 사유(집계 체계 차이)만 적는다.
**인과는 쓰지 않는다.**

## 게이트 ④ 종료 조건 — **확정 (2026-08-26)**

- **3편 발행 후에도 「1차 출처 링크 100%」·「린터 FAIL 0」을 못 맞추면 접는다.**
- ~~소스가 인천항을 월 단위로 분해하지 못하면 첫 편에서 접는다~~ → **이 조건은 실측으로 해소됐다.**
  `year`가 YYYYMM이고 `KRINC`가 월 40~42행으로 온다. **월 분해가 된다.**
- **명세 합 = 총계 검산이 두 번 연속 깨지면 접는다.** 소스의 집계 구조를 신뢰할 수 없다는 뜻이다.
- 기한: **첫 실호출 성공일(2026-08-26)로부터 3개월 — 2026-11-26.**
  그 안에 1편도 못 내면 종료 판정을 내린다(지침 §1.4 2층).
