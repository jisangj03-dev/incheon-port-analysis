# 유통 파일럿 — 실소요 시간 측정 [선커밋]

> **측정 전에는 어떤 발행 페이스도 숫자로 선언하지 않는다.**
> 이 파일은 그 측정의 선커밋 문서이고, 채워지기 전까지는 빈 칸이 정상이다.

## 왜 재는가

유통 부담은 티스토리 69편 동결의 남은 후보 셋 중 하나다(나머지: 제작 비용 · 소재 고갈).
**어느 것인지는 [미확인]이다.** 그래서 추정하지 않고 잰다.

지침 §7은 「측정 후에 페이스를 수치로 선커밋한다」고 정하고, §10-2·3은 그 전까지
**페이스 선언과 4순위 이하 채널 개시를 금지**한다. 이 측정이 그 금지를 푸는 유일한 열쇠다.

## 선커밋 — 데이터를 보기 전에 고정한다

| 항목 | 선언 |
|---|---|
| **대상** | **#07 발행분 1편** (2026-08-26 발행) |
| **측정 단위** | 분(minute). 초 단위로 쪼개지 않는다 |
| **측정 구간** | ① 요약 문안 작성 ② 이미지·카드 제작 ③ 게시·렌더 확인 |
| **채널** | 1위 GitHub 프로필 README · 2위 자체 사이트(허브) · 3위 링크드인 |
| **종료 조건** | **1편 측정 완료 시 종료.** 연장하지 않는다 |
| **회수물** | 아래 표 + 판정 |
| **판정 규칙** | 아래 「측정 후 판정」에 **미리** 적었다. 결과를 보고 고치지 않는다 |

## 측정 단위 정의 [2026-08-26 보강 · 측정 전]

판정 표의 분모가 정의돼 있지 않았다. **측정 후에 정의하면 선커밋이 아니므로** 여기서 고정한다.

| 용어 | 정의 |
|---|---|
| **채널 소요** | 한 채널에 1편을 올리는 데 든 시간 |
| **② 이미지 제작** | **편당 1회다. 채널마다 다시 만들지 않는다.** 한 벌을 만들어 3채널에 재사용한다(§7 「템플릿 1회 제작 후 재사용」) |
| **편당 합계(착수 포함)** | ①·③의 **전 채널 합** + ②의 **편당 1회분.** 첫 편의 실측치 |
| **편당 합계(반복분)** | 위에서 **템플릿 착수 시간을 뺀 값.** 다음 편부터 실제로 드는 비용 |

**판정 표의 분모는 「편당 합계(반복분)」이다.**

> **왜 반복분인가.** 첫 편에는 템플릿이 없다. 그 느림은 **반복 비용이 아니라 착수 비용**이고,
> 착수 비용으로 「유통 부담이 크다」고 판정하면 매번 처음 재는 셈이 된다.
> 다만 착수 포함값도 **버리지 않고 함께 기록한다** — 새 채널을 열 때 드는 값이 그것이다.

**§7 상한과 분모가 다르다.** §7의 「카드뉴스 1건 1시간」은 **② 한 벌**에 걸리는 상한이고,
아래 판정 표의 30/60분은 **편당 합계(반복분)** 다. 같은 「60」이 서로 다른 것을 가리키므로 적어 둔다.
②가 1시간을 넘으면 상한 초과로 기록하고, 템플릿화로 줄어드는지 다음 편에서 다시 잰다.

## 측정표 — 실측 후 채운다

| 채널 | ① 요약 작성 | ② 이미지 제작 | ③ 게시·확인 | 합계 | 비고 |
|---|---|---|---|---|---|
| GitHub 프로필 README | | | | | 1회성(편마다 반복 아님) |
| 자체 사이트(허브) | | | | | 원본. 채널이자 발행지 |
| 링크드인 | | | | | URL 한 줄 격하 유지 |
| **편당 합계(착수 포함)** | | | | | ②는 편당 1회분만 더한다 |
| **편당 합계(반복분)** | | | | | 위에서 템플릿 착수 시간을 뺀 값 ← **판정 분모** |

**기록은 손이 아니라 기계가 찍는다.** 「사후 회상으로 채우지 않는다」가 문장으로만 있으면
결국 나중에 기억으로 채우게 된다(사고 28의 구조). 시각은 `pilot_timer.py`가 남긴다.

```bash
python analysis/pilot_timer.py start linkedin summary   # 채널: github|site|linkedin
python analysis/pilot_timer.py stop                     # 구간: summary|image|post
python analysis/pilot_timer.py report --md              # 위 표에 붙일 형태로 출력
```

기록은 `docs/유통파일럿_기록.tsv`에 append-only로 쌓인다. **지우지 않는다.**
계측기는 **시간만** 다룬다 — 게시물 문안은 만들지도 저장하지도 않는다. 그것이 측정 대상이기 때문이다.
**템플릿 착수분을 빼는 것은 사람이 판단한다** — 기계는 「이번이 착수였는지」를 알 수 없다.

## 측정 후 판정 — 미리 적는다

| 편당 합계(**반복분**) | 판정 | 행동 |
|---|---|---|
| **≤ 30분** | 유통 부담은 병목이 아니다 | 채널 4·5위(커리어리·X) 개시 후보로 올린다 |
| **31~60분** | 감당 가능하나 상한에 근접 | 템플릿화 후 1편 더 재고 그때 판정한다 |
| **> 60분** | **유통 부담이 실재한다** | 채널을 늘리지 않는다. 3채널로 고정하고 편당 시간을 줄이는 쪽을 먼저 한다 |

**어느 경우에도 발행 페이스는 이 측정 하나로 선언하지 않는다.**
1편 측정은 표본 1이다. 페이스 선커밋은 최소 2편 측정 후에 연다.

## 이 측정이 답하지 못하는 것

- **티스토리 동결 사유는 여전히 [미확인]이다.** 유통 부담이 크게 나와도 그것이
  동결 원인이었다는 뜻은 아니다. 이 측정은 **지금의 부담**을 잴 뿐이다.
- **표본 1이다.** 첫 편은 템플릿이 없어 느리고, 그 느림은 반복 비용이 아니라 착수 비용이다.
