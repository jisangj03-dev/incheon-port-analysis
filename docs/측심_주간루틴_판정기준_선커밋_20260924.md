# 측심 주간 루틴 — 판정 기준 · 선커밋 (2026-09-24)

> **첫 실행 전에 쓴다.** 오너 위임문(2026-09-24 · 측심 주간 루틴 신설)이 준 기준 셋을
> 그대로 커밋한다 — 재고 나서 기준을 쓰면 기준이 결과에 맞춰진다(§3-7과 같은 이유,
> `docs/도구도입_선커밋_G6효용_20260910.md`와 같은 형식). **커밋 뒤 한 글자도 고치지 않는다.**
> 해시는 이 커밋의 메시지가 든다.

## 무엇을 재는가 — 대상

**측심 주간 루틴** — 주 1회(권장 월요일 06:00) 클라우드에서 돌아, 새 월 통계가 나왔으면
데이터·`reports/물동량.md` 갱신을, 아니면 이미 있는 월 데이터의 다른 단면으로 링크드인
게시 초안 1건을 만들어, **전부 PR 하나**로 올리는 루틴. 절차는 `.claude/skills/주간물동량/SKILL.md`.

## 기준 셋

### 기준 1 — PR 무수정 머지율
> **주 1회 PR이 오너 수정 없이 머지되는가.**

**재는 법**: `gh pr list --state merged --search "label:주간물동량"`(또는 브랜치 접두 `weekly-throughput/`)로
머지된 PR을 모으고, 각 PR을 `gh pr diff <번호>`와 머지 커밋의 부모 비교로 **머지 전 오너가
추가 커밋을 얹었는지**를 본다. 오너가 GitHub 웹에서 파일을 고치고 머지하면 머지 커밋 앞에
오너 커밋이 하나 더 있다 — 그것이 「수정」이다. 분모는 그 주까지 올라간 PR 전체,
분자는 오너 커밋 없이 머지된 것.

### 기준 2 — 업계 반응
> **8주(게시 8건) 안에 업계 사람의 반응(댓글·연결 요청·DM) 1건 이상.**
> **0건이면 단면이나 게시 형식을 바꾸되 갱신은 계속한다.** (루틴을 멈추지 않는다.)

**재는 법**: 세션은 링크드인에 로그인하지 않는다(지침 §4 게시 규율) — 이 칸은 **오너가
채널대기열에 적는다**. 8번째 게시 라운드가 닫히는 날, `docs/채널대기열.md`의 해당 행
메모에 반응 유무를 적고 이 문서를 참조한다. 0건이면 다음 주 루틴이 단면(수출입/터미널별/
공컨비율 중 하나)이나 문구 형식을 바꾼다 — **어떤 경우에도 주간 갱신 자체는 계속한다.**

### 기준 3 — 오너 시간
> **오너 시간 주 15분 이내(읽고 게시 클릭).**

**재는 법**: 관측 장치가 없다 — 자기보고다. 오너가 눈에 띄게 초과했다고 느끼면
`docs/채널대기열.md` 메모나 다음 위임문에 적는다. **초과가 2주 연속이면 루틴 산출물의
분량·검토 항목을 줄인다**(판단은 다음 세션 몫).

## 라운드의 정의

**한 라운드 = PR 하나 + 그 안의 게시 초안 하나.** 세션 수가 아니고 캘린더 주도 아니다 —
루틴이 격주로 건너뛰면(원천 미갱신 등) 그 주는 라운드에서 뺀다.

## 이 기준이 못 보는 것 — 알고 쓴다

- **기준 2는 세션이 직접 재지 못한다.** 링크드인 로그인·API를 안 쓰므로 반응 유무는
  전적으로 오너 보고에 의존한다. 오너가 안 적으면 이 기준은 판정 불능으로 남는다 —
  그것도 「0건」이 아니라 **[미확인]**으로 적는다.
- **기준 1은 「오너가 고쳤다」와 「오너가 다른 이유로 커밋했다」를 못 가른다** —
  같은 PR에 오너가 무관한 정리 커밋을 얹어도 이 잣대로는 「수정」으로 잡힌다.
  애매하면 PR 코멘트로 갈라 적는다.
- **기준 3은 관측이 아니라 느낌이다.** 시간을 재는 장치가 없고, 오너가 안 적으면
  이 기준도 판정 불능이다.
- **8주·15분 숫자 자체는 위임문의 선언값이다** — 이 라운드의 관측에서 나온 값이 아니다.
  G6 효용 기준의 T2(문서 참조)와 같은 자리 — 관측이 쌓이면 다음 위임문이 좁힐 수 있다.
