## 6. 기술 위생 — 승계된 사실
- 원시 파일 파싱은 **태그명 기준**. 위치 인덱스 금지.
- **API 응답 행 순서는 호출마다 비고정** [확정]. 2025 재수집분과 정본이 3,171B로 동일하나
  위치 기준 462셀 불일치, 자연키(`yyyy, mm, GInOut, ocCt`) 매칭 시 전 셀 완전 일치.
  → 대조는 **자연키 매칭으로만** 한다.
- 회귀 앵커 검증은 기존 CSV 재합산이 아니라 **동일 코드 경로로 재수집**해 맞춘다.
  재수집분은 별도 파일로 보존하고 정본을 덮어쓰지 않는다.
- 강한 앵커는 **git blob 해시 또는 SHA-256**. PowerShell `Measure-Object`의
  `-Line`(빈 줄 미포함) · `-Character`(한글을 1자로 계수)는 바이트가 아니다.
- **[2026-08-12 신규] 줄끝 정책은 앵커를 깰 수 있다.** `.gitattributes`에 `* text=auto eol=lf`를
  걸면 CRLF로 측정된 sha256 앵커가 checkout 시점에 전부 무효가 된다.
  정책을 세울 때는 **먼저 `git ls-files --eol`로 인덱스/워킹트리 실측**하고,
  쓰기 후 해시 스냅샷 대조로 부작용 0을 증명한 뒤에만 커밋한다.
- **[2026-08-12 신규] 경로식 검사 주의.** `git ls-files -- "파일명"`은 루트만 매칭한다.
  하위 폴더 파일은 `"*파일명"`으로 확인해야 한다. 잘못된 경로식은
  "미추적"이라는 **근거 없는 통과 판정**을 만든다.
- **[2026-08-12 신규] 문서 개정은 반드시 전문 납품.** 챗이 대화 중 준비한 개정안을
  "직전 본문 + 델타"로 지시하면 Claude Code에게는 원본이 없어 적용 지점이 사라진다.
  이번 세션에서 실제 발생했고 §5 가드(일치 개수 != 1이면 중단)가 잡았다.
  지침 §0 「이전 버전 참조 납품 금지」의 실증이다.
- API 응답 성공이 데이터 완전성을 보장하지 않는다. totalCount · 월별 존재 확인 필수.
  제로 패딩 주의("01" != 1). 음수 주장(존재 없음)은 양수 주장보다 엄격히 검증한다.
- X-CHECK는 양측이 서로의 값을 보기 전에 산출해야 실효가 있다. 챗 선공개 → Code 독립 산출.
  Code에게는 **판정결과 문서를 열지 말라**고 명시해야 독립성이 성립한다.
- 텍스트 정정은 `ReadAllBytes` → 치환 → `WriteAllBytes` 바이트 왕복으로만.
  `Set-Content` · `Out-File`은 BOM과 줄끝을 조용히 바꾼다.
  **대상에 따라 규격이 다르다 — 본부(OneDrive) md는 BOM+LF, 이 저장소 md는 BOM 없음·LF.** 섞지 마라.
- 편집 지시 전에 **대상 문자열의 현재 존재 여부부터 대조**한다. 일치 개수가 1이 아니면
  쓰기 전에 중단하는 가드를 붙인다. 가드 없는 Replace는 아무 일도 안 하고 "완료"만 보고한다.
- 검증 지표는 선언 전에 "그 수단이 대상을 실제로 집계하는가"부터 확인한다.
  실증: GitHub Insights > Traffic은 Pages 방문을 집계하지 않는다.
- 롤링 윈도우 지표는 당일 캡처. 지연 = 영구 소실.
- 발행 진실은 렌더된 화면 · 디스크 바이트 · git blob · tarball. 편집기 미리보기 신뢰 금지.
- 프로브는 값 비노출 설계(존재 여부 · 행 수 · 적재일만 출력).
- 이 IDE는 긴 명령에서 `EPERM: uv_spawn`으로 프로세스가 뜨지 않는다.
  긴 스크립트는 **내용 수정 없이** 덩어리로 분할해 순서대로 실행한다.
