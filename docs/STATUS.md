**정지선 ↔ 기전 대조표.** 지침 §4의 조항 문면과 **그것을 실제로 집행하는 코드의 명제**를
나란히 놓는다. **문면과 기전은 같지 않다** — 다르면 다르다고 적는 것이 이 표의 목적이다(사고 46).

> **이 블록은 생성된다. 손으로 고치지 마라.** 정본은 각 가드 파일의 `정지선-집행/명제/한계` 3줄이다.
> `python analysis/stopline_table.py --check` (부트블록 3번) · 갱신은 `--write`.

| 집행 파일 | §4 조항 (문면) | **이 코드가 집행하는 명제** | **닿지 않는 곳** |
|---|---|---|---|
| `git_pre_push.sh` | §4 — push는 운영자만 | `CLAUDECODE`가 있고 우회 변수가 없으면 **경로와 무관하게** push를 거부한다 | `.git/hooks/`는 **커밋되지 않는다**(새 clone엔 없음) · **`CLAUDECODE`는 지울 수 있다** · 세션 안 `!` 접두도 같이 막혀 `VIDIMUS_PUSH_OK=1`이 필요하다. **내 실수를 막는 난간이지 보안 경계가 아니다** |
| `hook_stopline.py` | §4 — push는 운영자만 / 커밋 전 앵커 검사 | Claude Code 도구 경로로 들어온 **명령 문자열** 중 push를 거부하고, commit 앞에서 앵커 검사를 돌린다 | **문자열만 본다** — `subprocess.run(['git','push'])` 같은 간접 호출은 못 막는다(실측). 2층이 그것을 받는다 |
| `lint_publish.py` | §4 — 데이터 지위(강등 구간·잠정치·박스 수 기준·`_99`·PASS) / §3 결론 자리 | 발행본과 채널 문안의 결론 자리에서 지위 위반·인과 서술·FACTS 미등재를 잡는다 | **결론 자리를 못 찾으면 `[구조]` WARN만 낸다** — 절 번호가 다른 문서는 검사되지 않는다(사고 26) |
| `safe_edit.py` | §4 — 문서 치환은 safe_edit로만. 일치 개수 ≠ 1이면 안 쓴다 | 이 도구를 거친 치환은 일치 1건일 때만 파일을 바꾸고 전후 SHA-256을 남긴다 | **이 도구를 안 거치는 편집은 못 막는다.** Write·Edit·리다이렉션은 그대로 통한다 |
| `verify_anchors.py` | §4 — 앵커 3건 수정·정렬·재저장 금지 / 봉인 2건 열람 금지 | 앵커 3건의 SHA-256이 기록값과 같고, 이 도구가 봉인 2건의 내용을 안 읽는다 | 다른 도구·사람이 앵커를 고치는 것은 못 막는다. 커밋 시점에 **사후로** 알려 줄 뿐이다 |

**정지선 중 코드가 집행하지 않는 것은 이 표에 없다** — 데이터 지위·공개 경계·문서 규율 일부가 그렇다.
**없다는 것이 곧 「사람이 지킨다」는 뜻이고, 그것도 사실이므로 적어 둔다.**
