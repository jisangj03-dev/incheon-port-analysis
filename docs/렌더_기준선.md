**측정: 2026-08-28 · Claude Code · 크롬 실물 조사**

## 왜 있는가

`docs/STATUS.md`가 「인천 `_config.yml` push가 발행본 렌더를 바꿀 수 있다 → push 직후
`report_07`을 열어 래퍼 클래스를 대조한다」고 적었는데, **대조할 기준선이 어디에도 없었다.**
「관측됐다」는 문장만 있고 **관측값이 어느 파일에 남았는지가 없었다**(운영자 검수, 2026-08-28).

**사후 대조는 기준선을 요구한다.** 기준선 없는 대조는 대조가 아니라 인상이다 —
사고 20(미리보기 말고 실물을 본다)의 다음 칸이다: **실물을 봤으면 본 것을 적어 둔다.**

**지금이 마지막 기회다.** 라이브 사이트는 커밋 `409fa2d` 기준이고 그 뒤 49커밋이 미push다.
운영자가 push하는 순간 이 상태는 사라진다.

## 이 측정이 갈라 준 것 — 셋

1. **front matter가 없어도 Jekyll이 레이아웃을 입힌다.** 발행본 8편 전부 front matter가
   없는데(실측) `generator: Jekyll v3.10.0` + primer 래퍼가 걸려 있다.
   **「_config.yml을 넣으면 렌더가 깨질 수 있다」는 걱정의 근거 절반이 여기서 사라진다** —
   레이아웃 적용 자체는 front matter에 걸려 있지 않다.
2. **푸터가 아예 없다.** 두 페이지 다 `footerPresent: false`.
   지침 §2.2-1의 「사이트 `/about`과 **전 페이지 푸터**」 중 **푸터 요건이 미충족**이다.
   (루트 본문에는 AI 표기가 있고, 발행본에는 하단 표기 블록(§2.2-2)이 있다. 없는 것은 **푸터와 `/about`**이다.)
3. **`htmlLang: "en-US"`.** 한국어 사이트가 `lang=en-US`로 나간다. primer 기본값이고
   `_config.yml`에 `lang`이 없어서다.

## push 후 예상 diff — **틀리면 그때가 신호다**

`_config.yml`이 `title: "Vidimus · 비디무스"` · `theme: jekyll-theme-primer`를 박았으므로:

| 항목 | 기준선 | push 후 예상 |
|---|---|---|
| `h1`(첫째) | `incheon-port-analysis` | **`Vidimus · 비디무스`** |
| `httpTitle` 꼬리 | `\| incheon-port-analysis` | **`\| Vidimus · 비디무스`** |
| `wrappers[0]` | `DIV.container-lg px-3 my-5 markdown-body` | **같아야 한다** (primer 명시 고정) |
| `generator` | `Jekyll v3.10.0` | 같거나 상위 |
| `tableCount` / `imgCount` / `imgBroken` | 7 / 2 / 0 | **같아야 한다** |
| `stylesheets` 쿼리스트링 | `?v=409fa2d…` | 새 커밋 해시 |
| `footerPresent` | false | false (푸터는 아직 안 만들었다) |

**`wrappers[0]`가 바뀌면 테마가 갈린 것이고, `imgBroken`이 비지 않으면 이미지 경로가 깨진 것이다.**
그 둘이 이 표의 핵심이다. 나머지는 바뀌는 것이 정상이다.

## 재측정 — 같은 값을 다시 뽑는 법

크롬으로 대상 URL을 연 뒤 콘솔에서:

```js
JSON.stringify({
  httpTitle: document.title,
  generator: (document.querySelector('meta[name=generator]')||{}).content || null,
  htmlLang: document.documentElement.getAttribute('lang'),
  wrappers: Array.from(document.querySelectorAll('body > *')).slice(0,4).map(e=>e.tagName+'.'+(e.className||'')),
  stylesheets: Array.from(document.querySelectorAll('link[rel=stylesheet]')).map(l=>l.getAttribute('href')),
  h1all: Array.from(document.querySelectorAll('h1')).map(h=>h.textContent.trim()),
  h2Count: document.querySelectorAll('h2').length,
  tableCount: document.querySelectorAll('table').length,
  imgCount: document.querySelectorAll('img').length,
  imgBroken: Array.from(document.images).filter(i=>!i.complete||i.naturalWidth===0).map(i=>i.getAttribute('src')),
  footerPresent: !!document.querySelector('footer'),
  bodyBytes: document.documentElement.outerHTML.length
}, null, 1)
```

## 닿지 않는 곳

- **한 시점의 한 기계에서 잰 값이다.** 캐시·CDN·브라우저 차이는 안 걸렀다.
- **시각적 동일성은 안 본다.** 폰트·여백·색은 이 지문에 안 잡힌다. 그것은 사람이 봐야 한다.
- **허브(`jisangj03-dev.github.io`)는 기준선이 없다** — 한 번도 발행된 적이 없어 잴 대상이 없다.
  **첫 push 직후가 그 기준선을 잡을 시점이다.**

## 2026-09-06 · 자체 레이아웃 뒤의 예상 지문 — 위 표의 「같아야 한다」를 대체한다

`_layouts/default.html` · `_includes/` · `assets/css/vidimus.css` 를 넣었다(경위 = `docs/작업기록.md`).
저장소의 `_layouts/` 가 테마(primer)의 것보다 먼저 잡히므로 **래퍼가 바뀌는 것이 의도**다.
위 「push 후 예상 diff」 표에서 `wrappers[0]` 「같아야 한다」는 이 절이 대체하고, `imgBroken` 「비어야 한다」는 그대로다.

| 항목 | 기준선(`409fa2d`) | 이제 기대하는 값 |
|---|---|---|
| `wrappers` | `DIV.container-lg px-3 my-5 markdown-body` … | **`A.skip` · `HEADER.mast` · `MAIN.` · `FOOTER.foot`** |
| `stylesheets` | `/incheon-port-analysis/assets/css/style.css?v=…` | jsDelivr 의 `pretendardvariable-dynamic-subset.min.css` · **`/incheon-port-analysis/assets/css/vidimus.css`** |
| `htmlLang` | `en-US` | **`ko`** |
| `h1all`(발행본) | `incheon-port-analysis` + 본문 H1 | **본문 H1 하나** |
| `httpTitle`(#07) | `… \| incheon-port-analysis` | **`#07 … · Vidimus · 비디무스`** — `page.title` 은 titles-from-headings 가 채운다. 제목이 `Vidimus · 비디무스`뿐이면 그 플러그인이 안 돈 것이다 |
| `footerPresent` | false | **true** |
| `tableCount` / `imgCount` / `imgBroken` | 7 / 2 / 0 | **같아야 한다** |

**틀리면 그때가 신호다.** `wrappers[0]` 이 `DIV.container-lg…` 로 남으면 레이아웃이 안 잡힌 것이고(jekyll-default-layout 이
안 돌았거나 `_layouts/` 가 안 올라간 것), `stylesheets` 에 `vidimus.css` 가 없으면 자산이 안 복사된 것이다.
**미리보기(`render_preview.py --site .`)로 본 것은 시각 결과일 뿐 이 지문의 확인이 아니다**(사고 20). 재측정 스니펫은 위 절 그대로 쓴다.
