# 측심 = 물류 사업 전체의 집 — 갈래별 성공·폐기 기준 (선커밋 · 2026-10-09)

> 만들기 전에 적는다. 이 문서는 고치지 않는다 — 바뀌면 새 날짜 문서로 낸다.
> 근거: 2026-10-07 오너 결정(jota PR #203 머지 댓글 — 「우리의 모든 물류 사업은 측심으로 뻗어나간다」, 측심 안에 크몽 연결을 둔다) · 2026-10-09 위임문(갈래 우선순위).
> 이 문서는 측심 저장소 안의 기준이다. jota 헌법·운영 규칙은 여기 옮겨 적지 않는다.

## 0. 무엇이 새로 들어오나

지금까지 측심은 **공공 1차 데이터로 인천 물류를 재는 발행 저장소**였다(`docs/측심_범위확장_20260930.md`). 10/7 결정으로 갈래가 하나 더 붙는다 — **셀러 물류 도구**(계산기·진단). 둘은 성격이 다르다.

| | 축(1~5번) | 셀러 물류 도구(이번에 여는 갈래) |
|---|---|---|
| 들어가는 숫자 | 공공 1차 데이터 | **사용자가 자기 견적서를 보고 넣는 값뿐** — 저장소에 금액·요율 상수 0 |
| 판정 | 가설 PASS/FAIL | 없음 — 계산과 「모름」 칸 세기만 |
| 출처 표기 | 원천 기관 | 칸 목록의 출처(셀러 설문 선택지 · 3PL 실무자 답신 구조) |

**축의 규칙(공공 1차 데이터만)은 도구에 적용되지 않는다 — 도구에는 데이터가 없기 때문이다.** 도구가 숫자를 들고 오는 순간(예: 택배 단가 기준선) 그 숫자는 축의 규칙을 다 따른다.

## 1. 갈래 1 — 셀러 물류비 자가진단 계산기 + 숨은 비용 4종

**뼈대는 jota `products/3PL견적비교표/build.py`(무료 엑셀)와 같다** — 청구 항목 10칸 × 표기 넷(별도 · 단가에 포함 · 없음 · 모름) × 블록 셋(지금 방식 · 견적 A · 견적 B). 같은 것을 두 번 만들지 않는다: 엑셀은 내려받아 쓰는 판, 계산기는 같은 뼈대를 브라우저에서 바로 쓰는 판이다. **칸 목록이 바뀌면 둘을 같은 날 고친다.**

### 1-1. 공개 전 완성 기준 (하나라도 못 넘으면 공개하지 않는다)
- **C1 같은 답**: 엑셀 가상 샘플과 같은 입력이면 같은 출력 — 월 합계 4,044,000 / 2,805,000 / 2,960,000원, 건당 4,044 / 2,805 / 2,960원, 모름 0 / 3 / 0개. 사람이 아니라 스크립트가 대조한다(불일치 0).
- **C2 외부 호출 0**: 외부 스크립트·글꼴·분석 도구·서버 전송 0줄. 입력값은 브라우저 밖으로 나가지 않는다.
- **C3 지어낸 금액 0**: 코드에 금액·요율 상수 0개. 숫자가 미리 채워지는 경로는 「가상 예시 넣기」 단추 하나뿐이고, 화면에 「가상값」이라고 적힌다.
- **C4 숨은 비용 4종**: 수광비 면적 배분 · 법적 비용(폐기 부담금 등) · 1회성 유통가공 · 유류비 연동 — 3PL 운영 실무자 답신(2026-10-07, 이름 비공개)의 **구조만** 옮긴다. 금액·비율은 받지 않았으므로 쓰지 않는다. 칸은 있음 / 없음 / 모름.
- **C5 휴대폰**: 360px 폭에서 가로 스크롤 0, 입력 칸마다 이름표.
- **C6 크몽 연결**: 결과 화면에서만, 판매 중인 상품만. 승인 확인 전 상품(829076, 10/8 기준 승인 대기)은 링크를 숨긴다.

### 1-2. 공개 뒤 판정 (판정일 = main 머지일 + 28일)
- **성공** — 아래 중 하나 이상:
  - 크몽 문의 중 출처 답이 「측심」·「계산기」인 것 1건 이상(jota `metrics/크몽_통계.md` §2 — 채팅이 크몽 화면에서 본 값만)
  - 계산기를 두고 온 피드백 2건 이상(LinkedIn 댓글·메시지·실무자 대화 — 이 칸이 빠졌다, 이 계산이 틀렸다 같은 것)
- **폐기** — 둘 다 0이면: 페이지는 그대로 두되(유지비 0) **셀러 갈래의 새 도구(반품비·택배 단가 계산기)를 열지 않는다.** 크몽 동선은 블로그 쪽에 맡긴다.
- 방문 수는 재지 않는다 — 분석 스크립트를 넣지 않기로 했으므로(C2) 잴 수단이 없다. 잴 수 없는 것을 기준에 넣지 않는다.

## 2. 갈래 2 — 물류창고 구·동 지도

- **입력**: `analysis/warehouse_by_gu.csv` · `warehouse_by_dong.csv`(이미 공개된 집계)뿐. **원본 행(상호·주소)은 쓰지 않는다** — nlic 행 단위 이용조건 확인 전.
- **모양**: 행정경계 파일·지도 타일은 출처·이용허락을 확인하지 못했으므로 쓰지 않는다(범위 확장 문서와 같은 판단). 대신 **구·군 개략 배치도** — 칸의 위치는 대략의 방향만 맞춘 것이고 실제 경계·거리가 아니라고 화면에 적는다.
- **완성 기준**:
  - M1 화면의 합계 = CSV 합계(480곳 · 8,884,623m²) — 스크립트 대조 불일치 0.
  - M2 페이지에 상호·주소·좌표 0.
  - M3 「개략 배치 — 실제 경계·거리 아님」 문구가 배치도 바로 아래.
- **판정(머지일 + 28일)**: 성공 = 창고 축 산출물로 실무자 반응 1건 이상(인천 창고 목록을 원했던 실무자에게 링크가 전달되고 답이 오는 것 포함 — 전달은 사람 손). 폐기 = 좌표 단계(`docs/주소좌표_판정기준_선커밋_20260930.md`)가 통과하면 개략 배치도는 점 지도로 **대체**한다(배치도는 좌표 0건 동안의 임시 그릇).

## 3. 갈래 3 — 항만 대시보드
- 이번 라운드는 기준만 적는다. 착수 조건: 갈래 1·2가 main에 들어간 뒤.
- 기준(착수 때 그대로 쓴다): 대시보드의 모든 값 = 주간 루틴이 갱신하는 CSV(`analysis/` 공개본)에서 계산, 손으로 옮긴 숫자 0. 판정 = 머지일 + 28일 안에 대시보드 링크를 쓴 게시물·기고 1건 이상, 없으면 대시보드를 접고 정리형 페이지(`reports/물동량.md`)로 충분하다고 본다.

## 5. 공통
- **크몽 연결**: 판매 창구 「데이터워크플로」는 측심·물류로그 어느 층에서도 링크할 수 있다(jota 브랜드 2층 결정 2026-09-30). 측심 지면에는 실명·연락처를 새로 넣지 않는다.
- **공개 = main 머지**: 머지가 발행 승인이다. 세션은 PR까지만 한다.
- **표기**: 도구 페이지에도 표기 블록을 단다. 생성 주체는 적지 않고, 검수는 한 만큼만 적는다.
