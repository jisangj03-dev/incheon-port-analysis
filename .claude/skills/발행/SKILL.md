# 발행 SKILL

> 이 파일은 **절차**만 담는다. 규범(왜 그렇게 하는가)은 지침에, 사고 기록은 `docs/사고기록.md`에,
> 수치는 `docs/FACTS.md`에 있다. **여기에 복제하지 않는다** — 복제본은 반드시 원본과 어긋난다.

## 0. 시작

```bash
git rev-parse HEAD        # 폴더 오인 차단. 그 외 시작 의례 없음
cat docs/STATUS.md        # 현재 상태·다음 할 일
```

## 1. 선커밋 (분석·이슈 라인)

판정 기준을 **데이터를 받기 전에** `docs/NN_주제검증.md` §4로 쓰고 커밋한다.
커밋 후 blob 해시를 기록한다.

```bash
git hash-object docs/NN_주제검증.md
```

기준을 커밋하기 전에는 수집 스크립트를 실행하지 않는다.
프로브가 필요하면 **값 비노출 설계**로만 (존재 여부·행 수·적재일·태그명).

## 2. 수집·게이트

- 게이트 구조는 재사용, **기대값은 편마다 새로 확정**한다. 미확정이면 착수하지 않는다.
- 게이트가 하나라도 FAIL이면 `sys.exit(1)`. 이후 단계로 가지 않는다.
- 게이트 항목의 정본은 이 파일이 아니라 **코드**(`analysis/*.py`)와 해당 편의 `NN_주제검증.md`다.
- **결합 게이트** (이종 데이터를 맞댈 때 필수): 단위·기간·집계 축 정합을 **맞대기 전에** 확인 /
  항등식은 데이터 무결성 확인이지 **결론의 근거가 아니다** / 비정수 배율은 단위 문제가 아니라 **축 불일치 신호**다.
- **차트는 커밋 전에 로컬에서 렌더해 눈으로 본다.** 편집기 미리보기를 신뢰하지 않는다(사고 20).
- **X-CHECK를 돌릴 때는 실행하는 쪽에 「판정결과 문서를 열지 말라」고 명시한다.**
  명시하지 않으면 정답지를 보고 산출해 대조가 형해화되고, 출력은 「불일치 0건」으로 똑같이 나온다(사고 25).

## 3. 본문 생성 (구조 B)

**먼저 형식 기준편 실물을 연다.** 분석 라인 기준편 = `reports/report_07_공컨테이너_표본외검증.md`.
제목 어순 · 계보 인용 블록 · 이미지 경로 · 캡션 방식 · 각주 위치 · 절 구성 · 표기 블록을
**파일에서 확인한다.** 기억이나 관례 추정으로 쓰지 않는다. 벗어나면 그 편차를 보고한다.
(분석 라인은 방법론 절을 두지 않는다 — §2.1·§2.5·부록이 이미 담는다.)

AI가 H1 부제 · 한 줄 결론 · §1 핵심 요약 · §2 · §3 해석 · §4를 생성한다.
**절 번호·표제를 바꾸지 않는다.** 린터가 `## 1.`·`## 3.`으로 결론 자리를 찾는다.

**결론 자리**(H1 부제 · 한 줄 결론 · §1 · §3)에 쓸 수 있는 수치는
`docs/FACTS.md`에 등재되고 지위가 `검증`/`관측`인 것뿐이다.
새 수치를 결론 자리에 쓰려면 **대장을 먼저 채운다.**

보고서 하단에 **표기 블록**을 반드시 넣는다 (형식은 `reports/report_07_*.md` 참조):

| 본문 생성 | 검수·발행 | 데이터 출처 | 재현 코드 |

## 4. 린터 — FAIL 0이어야 한다

```bash
python analysis/lint_publish.py reports/report_NN_*.md --show-exempt
python analysis/lint_publish.py --selftest    # 도구 자체 회귀 확인
python analysis/safe_edit.py --selftest       # 치환 가드 회귀 확인
```

- FAIL = 발행 금지. `참고`/`미확인` 수치가 결론 자리에 있거나, 데이터 인과 서술이 있다.
- **`[구조]` WARN = 발행 금지.** 결론 자리를 못 찾았다는 뜻이고, **그 구역은 검사되지 않았다.**
- WARN = 결론 자리의 미등재 수치. 대장에 창과 함께 등재한다.
- **인과 예외**(방법론 논리·인과 부인문)는 `--show-exempt`로 전부 열람하고 눈으로 확인한다.
  린터가 삼킨 것이 아니라 분류한 것이므로, 분류가 틀렸으면 문장을 고친다.

## 5. 운영자 검수 (편당 10분)

```bash
python analysis/review_pick.py reports/report_NN_*.md --log
```

① 결론 자리 통독 (3~4분) → ② 뽑힌 수치 1건 원본 대조 (3분) → ③ push (1분)

`--log`가 `docs/검수기록.md`에 한 줄을 남긴다.
**이 기록이 없으면 표기 블록의 「검수·발행: 운영자」를 달 수 없다.**

## 6. 커밋

```bash
git add <실제 편집한 파일만>      # git add . 금지
git diff --cached                 # 의도하지 않은 수치 변경이 있으면 정지
git commit
```

- 커밋 단위는 섞지 않는다. 특히 **표기·용어 재정규화를 본문 발행 커밋과 같은 커밋에 넣지 않는다.**
- 문서 수정은 **전문 덮어쓰기**. 치환은 **`analysis/safe_edit.py`로만** 한다 —
  일치 개수가 1이 아니면 종료코드 2로 중단하고 파일을 건드리지 않는다. 가드 없는 치환은
  아무 일도 안 하고 "완료"만 보고한다(사고 13·28).

```bash
python analysis/safe_edit.py <파일> --old <옛문자열> --new <새문자열>
python analysis/safe_edit.py <파일> --old <옛문자열> --check   # 세기만
```

## 7. push — 하지 않는다

**push는 운영자가 실행한다.** 공개 발행은 운영자의 서명이다.

발행 후: 렌더된 화면을 눈으로 확인한다 (편집기 미리보기 신뢰 금지).

## 정지선 (이 스킬이 자동으로 넘지 않는 지점)

1. 기준 미확정 · 기대값 미확정 → 착수 정지
2. 게이트 FAIL → 즉시 종료
3. 린터 FAIL → 발행 정지
4. 검수기록 없음 → 표기 불가
5. push → 운영자만
