# 발행 SKILL

> 이 파일은 **절차**만 담는다. 규범(왜 그렇게 하는가)은 지침(`본부\프로젝트지침.md`)에, 사고 기록은 `docs/사고기록.md`에,
> 수치는 `docs/FACTS.md`에 있다. **여기에 복제하지 않는다** — 복제본은 반드시 원본과 어긋난다.

## 0. 시작

```bash
git rev-parse HEAD        # 폴더 오인 차단. 그 외 시작 의례 없음
cat docs/STATUS.md        # 현재 상태·다음 할 일
```

## 1. 선커밋

판정 기준을 **데이터를 받기 전에** `docs/NN_주제검증.md` §4로 쓰고 커밋한다.
커밋 후 blob 해시를 기록한다.

```bash
git hash-object docs/NN_주제검증.md
```

기준을 커밋하기 전에는 수집 스크립트를 실행하지 않는다.

- **대장을 먼저 연다 — 프로브보다 먼저다.** 다룰 이름·대상이 `docs/FACTS.md`에 이미 행을 갖고 있는지 전수로 본다.

  ```bash
  python analysis/facts_worklist.py --names SNCT HJIT ICT E1CT IPT SICT
  ```

  **「이미 아는 사실」을 선커밋에 적을 때는 그 앎이 어디서 왔는지까지 적는다.**
  2026-09-11 실측: #11 §0-1이 두 표의 이름 차이를 「이미 본 어긋남」으로 적었는데,
  **대장의 `SICT` 행이 이미 「원문이 `- (폐쇄)`로 적은 부두」를 들고 있었다.**
  CSV 라벨은 봤고 대장은 안 봤다 — **선커밋은 blob이 증거라 안 본 채 적은 것이 그대로 굳는다.**
  그 행은 대장의 **비수치 정본 절**에 있어 `lint_publish.py`가 읽지 않는다. **린터가 안 읽는 것과
  대장에 없는 것은 다르다** — 그래서 이 대조는 `load_facts()`가 아니라 원문 줄을 읽는다.
- **모집단은 지표마다 따로 쓴다.** 「대상 다섯」을 머리에 한 번 적고 기준마다 안 적으면,
  실제로는 지표마다 다른 모집단이 한 수로 읽힌다(#11: T1·T2 부두군 3 / T3 합계 1+터미널 5 / T4 터미널 4).
- **선커밋 문서에는 판정 가능한 것만 쓴다.** 질문·창·모집단·단위·기준·검산까지다.
  기대·의의·「왜 중요한가」는 판정 후 문서에 쓴다.
  **커밋 전에 문장마다 「이것이 판정 대상인가」를 묻는다. 아니면 뺀다.**
  선커밋은 blob 해시가 증거라 **한 글자도 못 고친다** — 과장도 같이 굳는다(사고 38).
프로브가 필요하면 **값 비노출 설계**로만 (존재 여부·행 수·적재일·태그명).

## 2. 수집·게이트

- **창을 수집기의 기본값이 정하게 두지 않는다.** 원천이 **어디까지** 있는지 먼저 재고,
  그중 얼마를 쓰는지는 **적어서 고른다.** 안 쓰는 구간이 있으면 왜 안 쓰는지가 편에 남아야 한다.
  2026-09-11 실측: `collect_terminal_monthly.py`의 `list_posts()`가 게시판 목록에 `pageindex`를
  안 붙여 **첫 쪽 10건만** 읽는다. 목록은 **23쪽**이고 2006년까지 간다
  (`analysis/probe/probe_15_board_depth.py`). **#11의 「10개월」은 고른 창이 아니라 기본값이 정한 창이었다.**
  **깊이 재기는 값이 아니다** — 쪽수·글 제목만 보는 프로브라 선커밋 전에 쳐도 된다.
- 게이트 구조는 재사용, **기대값은 편마다 새로 확정**한다. 미확정이면 착수하지 않는다.
- 게이트가 하나라도 FAIL이면 `sys.exit(1)`. 이후 단계로 가지 않는다.
- 게이트 항목의 정본은 이 파일이 아니라 **코드**(`analysis/*.py`)와 해당 편의 `NN_주제검증.md`다.
- **결합 게이트** (이종 데이터를 맞댈 때 필수): 단위·기간·집계 축 정합을 **맞대기 전에** 확인 /
  항등식은 데이터 무결성 확인이지 **결론의 근거가 아니다** / 비정수 배율은 단위 문제가 아니라 **축 불일치 신호**다.
- **차트는 커밋 전에 로컬에서 렌더해 눈으로 본다.** 편집기 미리보기를 신뢰하지 않는다(사고 20).
- **X-CHECK를 돌릴 때는 실행하는 쪽에 「판정결과 문서를 열지 말라」고 명시한다.**
  명시하지 않으면 정답지를 보고 산출해 대조가 형해화되고, 출력은 「불일치 0건」으로 똑같이 나온다(사고 25).

## 3. 본문 생성 (구조 B)

**먼저 형식 기준편 실물을 연다.** 기준편 = `reports/report_07_공컨테이너_표본외검증.md`.
제목 어순 · 계보 인용 블록 · 이미지 경로 · 캡션 방식 · 각주 위치 · 절 구성 · 표기 블록을
**파일에서 확인한다.** 기억이나 관례 추정으로 쓰지 않는다. 벗어나면 그 편차를 보고한다.
(방법론 절은 두지 않는다 — 지침 §2.1·§2.5·부록이 이미 담는다.)

AI가 H1 부제 · 한 줄 결론 · §1 핵심 요약 · §2 · §3 해석 · §4를 생성한다.
**절 번호·표제를 바꾸지 않는다.** 린터가 `## 1.`·`## 3.`으로 결론 자리를 찾는다.

- **제목을 정한 뒤 「이 제목이 재지 않은 것」을 리드에 한 줄로 적는다.**
  제목은 짧아서 **본문보다 넓게 말하기 쉽다.** 2026-09-11·12 이틀에 두 번 났다 —
  #11 「다섯 곳을 **대표**하지 않는다」(잰 것은 부호 동행 하나) ·
  #12 선커밋 「창을 **되찾**는다」(220개월 중 39개월). **둘 다 본문은 정직했고 제목만 넓었다**(사고 116).
  `lint_publish.py` 가 제목에 넓이 낱말(되찾·대표·전부·전체·모두)이 있는데
  리드·§1 에 범위 한 줄이 없으면 **`[범위]` WARN** 을 낸다.
  **비율을 아는 제목이면 제목이 그 비율을 든다** — 「220개월 중 39개월」처럼.

**결론 자리**(H1 부제 · 한 줄 결론 · §1 · §3)에 쓸 수 있는 수치는
`docs/FACTS.md`에 등재되고 지위가 `검증`/`관측`인 것뿐이다.
새 수치를 결론 자리에 쓰려면 **대장을 먼저 채운다.**

보고서 하단에 **표기 블록**을 반드시 넣는다 (형식은 `reports/report_07_*.md` 참조):

| 검수·발행 | 데이터 출처 | 재현 코드 |

**[2026-09-02 · 지침 v6.2] 「본문 생성」 항목은 폐지됐다**(운영자 결정 · 개정 이력).
§2.2-4 — **사람이 쓰지 않은 것을 사람이 썼다고 적지 않는다.** 저작을 사람에게
돌리는 문장을 이 블록에 새로 넣지 않는다.

## 4. 린터 — FAIL 0이어야 한다

```bash
python analysis/lint_publish.py reports/report_NN_*.md --show-exempt
python analysis/lint_publish.py --selftest    # 도구 자체 회귀 확인
python analysis/safe_edit.py --selftest       # 치환 가드 회귀 확인
```

- FAIL = 발행 금지. `참고`/`미확인` 수치가 결론 자리에 있거나, 데이터 인과 서술이 있다.
- **`[구조]` WARN = 발행 금지.** 결론 자리를 못 찾았다는 뜻이고, **그 구역은 검사되지 않았다.**
- WARN = 결론 자리의 미등재 수치. 대장에 창과 함께 등재한다.
- **인과 예외**(방법론 논리·인과 부인문)는 `--show-exempt`로 전부 열람하고 눈으로 확인한다.
  린터가 삼킨 것이 아니라 분류한 것이므로, 분류가 틀렸으면 문장을 고친다.

## 5. 검수 — 하는 쪽이 한다 [지침 v7.0]

```bash
python analysis/review_pick.py reports/report_NN_*.md --log
```

① 결론 자리 통독 → ② 뽑힌 수치 1건 **원본 대조**(값만이 아니라 **창** — 기간·모집단·단위)

- **②는 §1.4 1층 항목이다.** 편마다 한 건 이상 한다. **누가 하는지는 안 정한다** — 운영자든 세션이든.
- `--log` 가 `docs/검수기록.md` 에 한 줄을 남긴다.
  **기록이 없으면 그 편에 검수 표기를 달지 않는다**(§2.2-4). **안 한 것은 안 했다고 적는다.**
- **검수는 발행 게이트가 아니다**(§2.3). 게이트는 린터(FAIL 0 · `[구조]` WARN 0)와 선커밋 보전이다.
  *종전 판은 이것을 「운영자 최소 역할 · 편당 10분 · ③ push」로 두었는데, 실측은 9편 중 기록 1건이었다 —
  서 있지 않은 게이트는 게이트가 아니라 거짓 표기의 원인이다.*

## 6. 커밋

```bash
python analysis/verify_anchors.py       # 정지선 앵커 3건 + 봉인 2건. 불일치면 커밋하지 않는다
python analysis/check_status_fresh.py   # STATUS 갱신 누락. 경고만 한다 — 차단은 --strict
git add <실제 편집한 파일만>            # git add . 금지
git diff --cached                  # 의도하지 않은 수치 변경이 있으면 정지
git commit
```

- **커밋 단위는 판단이다.** 다만 **표기·용어 재정규화를 본문 발행 커밋에 섞으면** 나중에
  「무엇이 발행이고 무엇이 정리인가」를 diff 로 못 가른다 — 그 이유로 안 섞는다.
- 치환은 **실패가 드러나는 경로로만** 한다(지침 §4-다). 일치 개수를 안 세는 치환은
  **아무 일도 안 하고 "완료"만 보고한다**(사고 13·28). `analysis/safe_edit.py` 가 그 경로를
  제공하지만 **유일한 경로는 아니다** — v7.0 이 도구 지정을 걷었다.

```bash
python analysis/safe_edit.py <파일> --old <옛문자열> --new <새문자열>
python analysis/safe_edit.py <파일> --old <옛문자열> --check   # 세기만
```

## 6.5 채널 문안 — 헤드라인도 결론 자리다

지침 §3의 결론 자리에는 **채널 게시물 헤드라인**이 포함된다. 보고서와 같은 규율을 받는다.
**[2026-09-09] 채널 파이프라인이 이 자리를 맡는다:**

```bash
python analysis/channels.py --list                     # 채널 규칙(형식·길이·되돌릴 수 있는가)
python analysis/channel_post.py --source <보고서>       # 문안 재료 — 쓸 수 있는 값만
python analysis/channel_queue.py --check --net         # 대기 중인 문안 전부 검사 + 대기열 갱신
python analysis/channel_queue.py                       # 「지금 뭐 대기 중이야」
```

문안은 `본부\채널문안\<id>.md`(머리말 + 붙여넣을 본문), 상태는 `docs/채널대기열.md`.
**게시 전에 알아야 하는 것 셋** — GeekNews 는 **두 시간 뒤 못 지우고 자기 것은 Show 로** 간다 ·
디스콰이엇은 **프로덕트 등록이 선행** · 링크드인은 **앞 140자**만 펼치기 전에 보인다.

아래는 그 안에서 도는 것이고, 문안 하나만 겨눌 때 직접 쓴다:

```bash
python analysis/lint_publish.py --channel <채널문안 경로> [<경로>...]
```

`--channel` 은 **파일 전문을 결론 자리로 본다.** 채널 문안에는 절 구조가 없어
일반 모드로 겨누면 `[구조]` WARN 넷만 내고 **값은 하나도 검사하지 않는다**(2026-08-26 실측).
허브 사이트 페이지도 같은 모드로 본다.

**게시 전에 돌린다.** 강등 지위 값(`참고`·`미확인`)이 헤드라인에 실리면 발행 금지다.

### 게시 단계 — 준비까지 하고 멈춘다

1. `channel_queue.py --check --net` 이 `준비` 로 올린 것만 후보다.
2. **문안 전문을 운영자에게 보이고 승인을 받는다.** 되돌릴 수 없는 채널(GeekNews)은 **필수**다.
3. **붙여넣기는 전사를 거치지 않는다** — `channel_post.py --clip <문안파일>` 이 본문을
   OS 클립보드에 넣고(되읽어 확인) **정본 해시**를 낸다. 브라우저에서 **Ctrl+V**.
   **본문을 스크립트·메시지에 옮겨 적지 않는다.** 2026-09-10 에 base64 를 옮겨 적다
   한 글자를 틀려 「그런」이 **「그럵」**으로 게시됐다(사고 109).
4. **대조는 파일과 한다.** 브라우저에서 공백 제외 SHA-256 을 재고
   `--verify <문안파일> --got <해시>`. **사본끼리 대면 어떤 정밀도로도 0이 나온다** —
   그날 「불일치 0」이 그랬다. 어긋나면 지우고 다시 넣는다.
5. 승인 뒤에 누른다. 그다음 `--set <id> --state 게시됨 --url <주소>`.
6. 그 주소를 열어 **카드가 실제로 떴는지 눈으로 본다**(태그가 있다는 것과 다르다 · 사고 73).
7. **게시한 뒤에는 그것이 그때의 기록이다.** 낡은 값을 현재로 고치지 않는다 —
   게시물의 시각이 창을 말한다. **아직 안 낡은 것을 미리 빼는 것**과는 다르다.
   **URL 이 여럿이면 어느 것에 카드가 붙는지는 [미확인]이다**(사고 110) — 순서를 바꾸면 바뀐다.

**로그인·자격 증명은 다루지 않는다.** 세션이 만료돼 있으면 **알리고 멈춘다.**
로그인해서 올리는 자동 제출 스크립트는 만들지 않는다.

## 7. push — 세션이 친다 (v6.4)

**push 와 배포는 Code 가 한다.** 커밋 뒤 `git push origin main`. 측심은 `python tools/push.py` →
`higgsfield website deploy <id>` → `status` 로 `deployed` 확인(`../sounding/tools/RUNBOOK.md`).
**pre-push 가 난간을 돌린다** — 검수 기록(`check_review_log`) · ~~생성물 신선도~~(비었다 · 2026-09-12 · 사고 115) ·
대장 · 접근성 · 셈 · Jekyll · **공개 유출** · 사이트 상수.
**⑦ 공개 유출만 차단이고 나머지는 경고다** [v7.0]. 기준은 하나 — **push 가 되돌릴 수 없게 만드는 것만 막는다.**
경고로 걸린 것은 stderr 를 읽고 push 뒤에라도 고친다. ⑦ 에 걸리면 **고치기 전에는 안 나간다** —
유출은 이력에 남고 지우려면 이력 재작성(§4 가 · 운영자)이다. 여기서 미리 보려면:

```bash
python analysis/check_review_log.py     # 지금 밀면 검수 없이 나가는 편이 있는가
```

**§5의 「기록이 없으면 표기를 안 단다」가 여태 문장뿐이었다.** 2026-08-27에

## 정지선 (이 스킬이 자동으로 넘지 않는 지점)

1. 기준 미확정 · 기대값 미확정 → 착수 정지
2. 게이트 FAIL → 즉시 종료
3. 린터 FAIL 또는 `[구조]` WARN → 발행 정지
4. 검수 기록 없음 → **검수 표기 불가**(발행 정지가 아니다 · `check_review_log.py` 가 push 순간에 경고)
5. **공개 유출**(실명·개인 이메일·인증키) → **push 정지.** 난간 ⑦ 이 막는다
6. 힘 push · 이력 재작성 · 저장소 삭제 · 토큰·자격 증명 · 계정 조작·게시 → **운영자만**
   (push·배포·커밋·지침 개정 자체는 세션 몫이다 · v6.4 · v7.0)
